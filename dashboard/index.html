Where the events come from

An event log needs three things per row: something that groups rows into a case, a name for the step, and the moment it happened. The defaults read Salesforce's OpportunityHistory, which records one row per stage change and is on by default. Point them anywhere that shape holds — custom objects included.

Where the data comes from

    
This dashboard reads a connected application directly. There is no import step
    and no sample data — if nothing is connected, there is nothing to show, which
    is the honest state rather than a placeholder.

    
The event log is one query: the object you name, ordered by case and time. Every
    count, path, and edge below is derived from those rows in your browser. Nothing is
    sent anywhere, and the query runs with your own credentials.

    
A process needs events ordered in
    time. Where a source stamps every row at load time, no ordering exists and the
    dashboard says so instead of drawing a model that would be invented. For a mined
    model with gateways and soundness guarantees, export a log and run
    pmx discover.
